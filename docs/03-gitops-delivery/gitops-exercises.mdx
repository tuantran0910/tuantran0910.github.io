## Simulate an SSA field conflict

Start with `team-a` owning `spec.replicas: 3`. Try applying five as `team-b`. After the conflict, apply three to share ownership. Then try to change the shared value and observe what happens with and without force. The simulator models one field on an existing object. The cluster lab also covers how an owner can relinquish the field by omitting it from its next intent.

## Compare atomic and keyed list ownership

The same resource contains payment and logging backends. In the atomic case, Manager A owns the whole list. In the keyed case, Manager A owns the payment fields and the logging entry identity, and the live logging URL has no owner. Manager B starts with no ownership. Toggle the list schema, submitted intent, and force option. Each selection starts with the same live state.
